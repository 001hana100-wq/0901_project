# 2. 프로필 콘텐츠 작성 양식

페이지 구현 전에 아래의 대괄호 부분을 실제 정보로 교체합니다. 공개하고 싶지 않은 항목은 삭제할 수 있습니다.

## 2.1 기본 프로필

| 항목 | 작성 내용 |
|---|---|
| 이름 | `[홍길동]` |
| 직무/역할 | `[프론트엔드 개발자]` |
| 한 줄 소개 | `[사용하기 편리한 웹 서비스를 만드는 개발자입니다.]` |
| 거주 지역(선택) | `[서울, 대한민국]` |
| 프로필 이미지 | `frontend/assets/images/profile.webp` |
| 이미지 대체 텍스트 | `[홍길동의 프로필 사진]` |

프로필 사진을 사용하지 않는 경우 본인을 표현하는 일러스트나 대표 이미지를 사용할 수 있습니다. 사용 권한이 있는 이미지만 등록하고 웹에 적합한 크기로 최적화합니다.

## 2.2 자기소개

두세 문단 안에서 현재 하는 일, 관심 분야, 목표 순서로 작성합니다.

```text
안녕하세요. [직무/역할]로 활동하고 있는 [이름]입니다.
[주요 관심 분야와 지금까지 해온 일]에 관심을 두고 있습니다.

[일할 때 중요하게 생각하는 가치]를 바탕으로
[앞으로 만들고 싶거나 성장하고 싶은 방향]을 추구합니다.
```

## 2.3 본인의 강점

강점은 3개 정도로 정리하고, 추상적인 표현만 쓰지 말고 근거를 함께 적습니다.

| 강점 | 설명 또는 근거 |
|---|---|
| `[문제 해결]` | `[문제를 작은 단위로 분석하고 원인을 찾아 개선합니다.]` |
| `[협업과 소통]` | `[진행 상황과 결정 사항을 문서로 명확하게 공유합니다.]` |
| `[꾸준한 학습]` | `[새로운 기술을 작은 프로젝트에 적용하며 익힙니다.]` |

## 2.4 기술 사항

기술은 분야별로 나누고, 실제로 사용한 기술만 작성합니다. 막대그래프 형태의 임의 숙련도보다 활용 경험을 간단히 설명하는 방식을 권장합니다.

| 분야 | 기술 예시 | 활용 내용 |
|---|---|---|
| Frontend | `HTML5, CSS3, JavaScript` | `[반응형 UI와 사용자 상호작용 구현]` |
| Framework | `[React, Vue 등]` | `[컴포넌트 기반 화면 구현 경험]` |
| Backend | `[Node.js, Java, Python 등]` | `[API 또는 서버 구현 경험]` |
| Database | `[MySQL, PostgreSQL 등]` | `[데이터 모델링과 CRUD 구현]` |
| Tools | `Git, GitHub, Figma` | `[버전 관리, 협업 및 디자인 확인]` |

사용하지 않는 분야는 표에서 제외합니다.

## 2.5 프로젝트

프로젝트는 완성도와 관련성이 높은 순서로 2~4개를 소개합니다. 각 프로젝트마다 다음 정보를 준비합니다.

### 프로젝트 작성 양식

```text
프로젝트명: [프로젝트 이름]
진행 기간: [YYYY.MM ~ YYYY.MM]
한 줄 설명: [어떤 문제를 해결하는 프로젝트인지 설명]
주요 기능: [기능 1], [기능 2], [기능 3]
담당 역할: [직접 구현하거나 기여한 내용]
사용 기술: [HTML], [CSS], [JavaScript]
결과/배운 점: [성과 또는 개선한 점]
대표 이미지: frontend/assets/images/[project-name].webp
GitHub: https://github.com/[사용자명]/[저장소명]
데모 주소(선택): https://[배포 주소]
```

팀 프로젝트라면 프로젝트 전체 성과와 본인이 담당한 내용을 구분해서 작성합니다. 공개 저장소가 없거나 데모가 종료된 경우 해당 링크 버튼을 표시하지 않습니다.

## 2.6 연락처와 외부 링크

| 항목 | 작성 내용 | 공개 권장 여부 |
|---|---|---|
| 이메일 | `[name@example.com]` | 필수 |
| GitHub | `https://github.com/[사용자명]` | 필수 |
| 전화번호 | `[010-0000-0000]` | 선택 |
| LinkedIn | `https://www.linkedin.com/in/[사용자명]` | 선택 |
| 블로그 | `[블로그 주소]` | 선택 |

이메일 링크는 `mailto:name@example.com` 형식으로 연결합니다. 전화번호처럼 민감한 정보는 공개 웹페이지에 꼭 필요한지 먼저 확인합니다.

## 2.7 페이지에 사용할 최종 정보

구현을 시작하기 전에 다음 항목을 확인합니다.

- [ ] 이름, 직무와 한 줄 소개
- [ ] 사용 권한이 있는 프로필 사진 또는 대표 이미지
- [ ] 자기소개 문장
- [ ] 근거가 포함된 강점 3개
- [ ] 실제 사용 경험이 있는 기술 목록
- [ ] 프로젝트 2~4개의 설명과 이미지
- [ ] 정확한 이메일 주소
- [ ] GitHub 프로필 및 프로젝트 저장소 주소
- [ ] 공개할 기타 연락처
